# 8848 PDF — demo film

A ~68-second silent, captioned film demonstrating the engine, built with
[Remotion](https://remotion.dev). **Internal artifact** — every frame carries
an "Internal — not for distribution" marking.

Output: `out/pdf-ai-demo.mp4` (1920×1080, 30fps, ~8.7 MB).

## The one rule

**Nothing in it is a mockup.** Every product frame is a real screenshot of
the real application, captured by a script that drives it. Every number and
every quoted model output comes from a real run. If a moment can't be
captured, it gets cut rather than faked.

## What it argues

Most tools that claim to redact a PDF draw a black box and leave the text in
the file. The film's centrepiece builds *both* outcomes from the same source
document and reads them the same way — by extracting text, as a recipient
would:

| | what the page looks like | what copying the text gives you |
|---|---|---|
| black box drawn over it | redacted | `512-34-9081` |
| this engine | redacted | nothing |

That comparison is generated by `proof.py`, not asserted.

## Regenerating

Captures are committed, so rendering needs neither a server nor a model.
Regenerate them only when the UI changes.

```bash
# 1. the app and a local model must be running
cd .. && ./.venv/Scripts/python.exe -m uvicorn webui.main:app --port 8130
ollama serve            # with qwen3:14b pulled

# 2. drive the real app and record it  (~2 min: the model genuinely runs)
cd demo && npm run capture

# 3. rebuild the naive-vs-engine comparison
../.venv/Scripts/python.exe proof.py

# 4. render
npm run render
```

`npm run studio` opens Remotion's editor for iterating on timing, and
`npx remotion still src/Root.tsx Film out/x.png --frame=N` renders a single
frame — the fastest way to review a scene.

## Layout

```
capture.mjs          drives the real app, writes public/captures/*.png
proof.py             builds the naive-vs-engine comparison and renders both
src/theme.ts         Nord tokens copied from the product's own stylesheet;
                     also the scene timings — retime the film from here
src/Film.tsx         the spine
src/scenes/          one component per beat
src/components/      Callout, Caption, Screen, Terminal, InternalTag
public/captures/     committed real frames + proof JSON (the "fixtures")
```

## Notes for whoever touches this next

- **Scene timings live in `theme.ts`**, not scattered through the scenes.
- **Callout coordinates are fractions of the source image**, so they survive
  a shot being resized or re-cropped. `AnnotatedShot` deliberately clips the
  image but *not* the annotation layer — clipping both truncates every label.
- **The model run really did take ~98 seconds.** The film shows the real
  footage with the dead time compressed; the result is not sped-up fakery,
  but don't remove the "97.8s" caption without checking `proof.json`.
- **Do not claim a raw-byte search as proof.** PDF writes text with per-glyph
  positioning, so a literal digit run isn't contiguous in the bytes even in
  an untouched original — a byte search reads as proof while proving nothing.
  `proof.py` says so in its own output.
- There is no audio track of substance and no voiceover. It is meant to read
  muted.
