### New Breakage in the Fix Diff

1. **Important (security)** — `engine/geometry.py:245` bounds only `page.mediabox` and `page.cropbox`, not the transform's e/f or `page.rect`, and PyMuPDF's fallbacks can make an unrenderable page look like a plain letter page to all four other rules. `/MediaBox [-2147483648 -2147483648 2147483520 2147483520]` is MuPDF's `fz_infinite_rect`: `JM_mediabox` and `JM_cropbox` fall back to letter, `Page.bound()` substitutes (0,0,612,792) when `fz_bound_page` is infinite, and `pdf_page_transform` gives (1,0,0,-1,2^31,2^31) with a clean rotation-0 pattern. Every rule passes for both kinds, while MuPDF's real page bound is 4.29e9 pt wide, inserted text cannot be read back and the VISIBLE span cannot be found to redact. This is the "any" class (`unit0`): a page whose probe is unrenderable must be refused. The verdict depends on global state: with an empty MuPDF warning buffer `page.rect` raises `IndexError` (PyMuPDF's bug at `pymupdf/__init__.py:11022`), but a document that also carries a broken `startxref` makes MuPDF repair on open, which fills the buffer, and then the same page is allowed deterministically — verified with `standard(INF)` + `startxref 999999` (`cand5.py`, `ATTACK` rows, current gate `('-', '-')`, probe `(None, None)`). The round-2 code (`transformation_matrix` at rotation 0 is this same ctm) would have allowed it too, so it is not a regression, but the magnitude rule is the rule that should see it. Verified repair (`cand5.py`): include `ctm.e`, `ctm.f` (from the `page_transform` result already in hand) and the four values of `page.rect` in the magnitude check; 0 changes on the 1,024 matrix, every INF-plus-warning row refused "larger than", INF `/CropBox [0 0 612 792]` still allowed and still exact. Add Test B rows `media-inf-repaired` (the broken-`startxref` build, category `huge`) and `media-inf-crop-letter` (`-`), and a redaction row for the latter. Note the bare INF row cannot be a table row without the warning (its `doc[0]` raises).

2. **Important (threshold)** — `engine/geometry.py:122` `_MAX_COORDINATE_PT = 2 ** 24` was ruled from my round-2 measurement, which was integer-only: `drift_probe` writes at (100, 140) on pages whose origin is 0, so every coordinate it wrote was an exact float32 integer, and "no drift at 2e7" was true only of that probe. Fractional coordinates — which is what font metrics, bboxes and the editor's own points are — round to half the float32 spacing: measured drift at the far corner is 0.0031 pt at 2^18, **0.0125 at 2^19**, 0.05 at 2^22, 0.2 at 2^23, and **0.3 pt at 1e7 and at 2^24** (`round4.py frac`), against the gate's own 0.01 tolerance. The same happens on an ordinary-sized page merely offset (`[10000000 0 10000612 792]`: text at (100.3, 140.7) lands at (100.0, 140.7)). Page space is not bounded at all: `[-16777216 0 16777216 792]` and `[-16777216 0 612 792]` keep every box coordinate within 2^24 but put content at page x ≈ 2^24+100, where the float32 grid is 2 pt: `get_text` returns "VISIBL E" (a spurious space, so a text-keyed replace or redact finds nothing) and char boxes at 2-pt granularity. Verified repair (`cand4.py`, `cand5.py`): bound `page.mediabox`, `page.cropbox`, `page.rect` and the ctm's e/f at **2^18** (262,144 pt, 92 m; the spec's page limit is 14,400 pt): worst fractional drift on an allowed page 0.005 pt; 0 changes on the 1,024 matrix; among the 223 rows only pages of 2^20 pt and up change, all from allowed/over to "larger than" (`media-huge-1e7`, `media-huge-offset`, `unit-1.00001-huge-offset`, the 2^20-2^24 rows). Test B's `media-huge-1e7` row then becomes `huge`, and the drift probe should gain a fractional-position variant (e.g. (x-100.3, 140.7) at the far edge) so a future bound change is measured against what the editor actually writes. The message text "larger than 262144 points" and the docstring at `:197-201` need the new number and the corrected reason (half the float32 spacing exceeds 0.01 pt from 2^19 on; page space and the transform's translation count too).

3. **Minor** — `tests/test_geometry.py:689` `assert offset <= 0.5`: every measured offset on the 26 rows is 0.0 (bbox and fill pass through the same float32 grid), and 0.5 pt is exactly the half-spacing of [2^23, 2^24), i.e. the tolerance was set at the size of the drift class this rule exists for. Tighten to 0.01 (matches `drift_probe`), and at `:681` filter the fills by the green colour that was passed in (`drawing["fill"] == (0, 1, 0)`) rather than any non-None fill, so a page with pre-existing fills or a fill of the wrong colour cannot satisfy "exactly one fill".

4. **Minor** — `tests/test_geometry.py:596-646` `_REDACTION_ALLOWED_ROWS` re-types each table row's page parameters by hand; the sync guard at `:648-654` compares ids only, so a row's builder can change in `_ADVERSARIAL_TABLE` while the redaction copy silently keeps the old page (the B2 and `dangling-parent` copies are already hand-built `build([...])` objects). Store the parameters `(page_extra, pages_extra, extra_objects)` once per row and derive both `standard(...)` and `with_text(...)` from them (with `build` for the two custom-parent rows), so the guard covers the page and not just the id.
